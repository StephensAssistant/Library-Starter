# AI Hats — `HAT`

A role the Librarian (the assistant) wears depending on the work in front of it — GitHub-native equivalent of the old Drive Library's CHARTER-* / seat concept (Head Librarian, Architect, Builder, Tester, Validator, and the rest). Same agent, different hat, per the task.

Filenames: `HAT-<NNNN>-<slug>.md`

Added 2026-08-23, per the Library owner's explicit sign-off (§1a) — the tenth governed type, following the same pattern Playbooks and Skills were added under.

Create from `_TEMPLATE.md` using `_HOW-TO-CREATE.md`.

## Before changing this folder

- Create a Hat only for a distinct role; otherwise amend the existing canonical Hat.
- For a new record, reserve the `HAT` ID, satisfy the base frontmatter contract, use only `current` or `superseded` status, and add evidence-backed reciprocal links.
- Confirm the Hat records scope, evidence, verdict, residual risk, owner, and hand-off.

## Mandatory action routing

Assess this complete current roster before material work, then activate every Hat whose responsibility is required. Reassess at action/evidence changes. Apply the associated Skills and dependencies; do not substitute a familiar Hat for a specialist or activate unrelated roles merely to increase coverage. These entry points restore visibility, not new permissions or an independence claim.
