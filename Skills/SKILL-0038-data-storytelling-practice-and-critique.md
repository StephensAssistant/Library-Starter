# Evidence-Led Data-Story Peer Critique

Reusable capability for collecting evidence-led peer critique of a data-storytelling artifact.

## When to use

Use only when the requested action is collecting evidence-led peer critique of a data-storytelling artifact. Use the independent action-specific Skills for adjacent validation, recovery, testing, performance, rehearsal or delivery work.

## Intent-routing contract

This Skill owns this one action from authoritative inputs to its evidenced result. It does not absorb adjacent jobs merely because they use the same platform or subject.

## Method

1. Confirm authoritative inputs, scope and success condition.
2. State audience, decision and intended takeaway; ask reviewers what they noticed, inferred and would do next; compare observed interpretation with intent; critique the artifact rather than its author.
3. Preserve evidence, assumptions, result and any unresolved material gap.


### Application checks

Give reviewers the actual artifact, audience and intended decision; retain their noticed pattern, inferred meaning and proposed next action as observations. Compare those observations with the intended takeaway and locate the specific visual or wording that caused a mismatch. Return prioritised artifact findings with supporting feedback and unresolved disagreement. Where no peer feedback was obtained, label the result an author assessment rather than claiming a peer-validated interpretation.

## Evidence expected

Retain the inputs, checks, chosen result, source/date context and any condition that requires reassessment.

## Benchmark case

Reviewers miss the intended comparison in a five-line chart; their observations identify the specific encoding problem before any aesthetic debate.

Boundary design case: reviewers disagree about the chart takeaway. Retain their actual observations and the intended message separately; identify the affected encoding or unresolved interpretation without inventing consensus, changing the data, or treating author preference as peer evidence.

## Anti-patterns

- Expanding this Skill into another action because the subject is similar.
- Treating tool success or polished output as verified evidence.
- Proceeding through an unresolved material input or authority gap.

## Stop

Stop when the authoritative input or success condition is unknown. Route the next distinct action to its own Skill.
