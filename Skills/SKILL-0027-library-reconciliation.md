# Reconciliation

Bringing every generated view back into agreement with the source records.

**Used by:** `PLAY-0056` (commit), `PLAY-0055` (merge), `PLAY-0037` (hygiene).

## Why this exists

The final staged source state owns canonical source and mandatory companions; the staging workflow owns generated outputs.

The workflow validates the pinned source SHA, builds the fixed point, proves byte-idempotence and admits only known generated paths. If generated bytes changed and staging still equals that source SHA, it persists deterministic generated changes through guarded workflow-owned reconciliation, validates the exact final head and publishes `candidate-ready` for it. If nothing changed, it validates and attests the source SHA directly.

## The sequence

The staging workflow runs the affected builders selected by `final_candidate_checks.py`. Later builders consume earlier output, and unchanged optional views are left alone.

```
final_candidate_checks.py main --scratch-candidate
validate generated-path allowlist
commit generated outputs only when required
final_candidate_checks.py main --confirm
```

## Prove idempotence

`final_candidate_checks.py` repeats affected builders when their implementation or shared inputs changed. If the second tree differs, investigate before committing.

## Generated does not mean exempt

Current source classification distinguishes code review from validation scope; neither classification is execution proof.

| Canonical output | Code/config review classification | Validation-scope classification |
|---|---|---|
| `Catalog/BOARD.md`, `TAG-INDEX.md`, `SESSION-PACK.md`, `ARTIFACT-DUPLICATES.json`, `SYSTEM-HEALTH.json`, `INTENT-REGISTRY.json` | Fixed-point output; excluded | Derived path; does not force full mode |
| `Catalog/Project-Context/PROJ-<NNNN>.md` | Fixed-point output; excluded | Derived path; does not force full mode |
| Governed folder `index.md` | Fixed-point output; excluded | Not universally exempt; may force full mode under the path rules |

Source: `.github/scripts/code_review_scope.py` (`fixed_point_output`, `is_reviewable_code`) and `.github/scripts/validation_scope.py` (`DERIVED_PATHS`, `classify`). Authored changes to builders, routing configuration or other reviewable code still require the applicable independent review. Validate the exact changed paths through the current authorised workflow; do not infer a meaningful-change exemption, successful reconciliation, review or candidate acceptance from these classifications.

## If you cannot run generators

Complete the authorised canonical source state on staging and report source hand-off with candidate validation pending. A save or mechanical commit does not authorise reconciliation, candidate validation or Actions. Enter PLAY-0056 only under AGENTS.md Library rule6’s approved daily schedule, standalone named one-off exception, or recorded entry grant from an explicitly invoked already-approved workflow that actually declares PLAY-0056. Source construction, review or source-only FLOW-0001 is not that grant. During that authorised run, follow only workflow-proven reconciliation and exact final-head evidence; never claim local execution.

## Anti-patterns

- Running a subset of the sequence
- Running it once and assuming idempotence
- Hand-patching a generated file to make a check pass
- Allowing the bot to commit a path outside the generated-output classifier
- Treating a `mode: full` result as a bug
- Manually creating the workflow-owned reconciliation commit

## Failure recovery

**Second pass differs:** something is non-deterministic, or a source file is inconsistent. Investigate. Do not just run a third time and hope.

**Workflow rejects a generated path:** a builder or link healer changed canonical source. Repair that source in a new authorised source update; never widen the bot allowlist to hide the defect.

**Staging advanced during reconciliation:** preserve the advance and stop the stale write. Do not absorb concurrent source changes or rebuild automatically. Only a currently authorised Commit route may use its explicit bounded stabilisation or workflow-proven reconciliation exception; otherwise report the changed head and blocked hand-off.

## Benchmark case

After canonical records change, run the governed reconciliation to regenerate derived views, then run it again and prove the second pass produces no further differences.

## Stop

Stop at source hand-off with validation explicitly pending when no run is authorised. During an authorised run, stop when canonical inputs and owned derived outputs reach the verified fixed point and exact-head acceptance, or report the precise instability/failure. Completion, failure or stop ends that single-use run authority; a repair does not authorise another run.
