# Data Storytelling Deliberate-Practice Design

Reusable capability for designing one focused, observable data-storytelling practice exercise.

## When to use

Use only when the requested action is designing one focused, observable data-storytelling practice exercise. Route adjacent actions to their own confirmed Skills.

## Intent-routing contract

This Skill owns this action from evidence intake through its stated result. It does not own adjacent architecture, implementation, approval or deployment work.

## Method

1. Confirm the learner, one observed capability gap, source artifact/data and the evidence that will show improvement for this exercise.
2. Choose one capability gap, create a disposable first attempt, define evidence of improvement and capture one reusable lesson.
3. Preserve evidence, assumptions, exceptions and the resulting decision or verified output.
4. Stop or escalate when a missing fact could materially change the result.

## Evidence expected

Retain the inputs used, checks performed, result, unresolved gaps and source/date context needed to reproduce the action.

Return a focused exercise, disposable first attempt, comparison criterion and captured lesson when performed; distinguish a designed exercise from observed improvement.

## Benchmark case

A session targets clutter reduction only and records which removal improved comprehension.

Boundary design case: The exercise changes clutter, colour and message simultaneously. Narrow it to the chosen gap before attributing improved comprehension to one removal; no observed comparison means no improvement claim.

## Anti-patterns

- Expanding this Skill into adjacent jobs.
- Treating an unverified assumption or tool success as outcome evidence.
- Hiding a material gap to produce a cleaner answer.

## Stop

Stop when the authoritative input, required access or success condition is unknown. Do not claim completion without evidence of this Skill's specific result.
