# Status Update Composition

Compose a concise evidence-based progress update.

## When to use

Use for project, ticket, end-of-day, handover or executive status communication.

## Method

1. Separate fact, current state, forecast and assumption.
2. Lead with achieved outcomes and their evidence.
3. Explain material variance from the previous expectation.
4. Include only material wait, blocker or dependency state.
5. End with the next decision-changing action.
6. Compress repeated work-log detail into meaningful highlights.

## Decision and evidence details

Use the current governing work record and dated evidence for the reporting period. Preserve the distinction between achieved, in progress, waiting and forecast; make material gaps visible without turning them into achievements. Delivery of the draft is separate from sending it.

Boundary design case: queries ran but no accepted outcome is evidenced. Report the actual investigation state and next decision-changing action; do not describe tool activity as an accepted result.

## Benchmark case

A day included several queries and meetings but only one accepted outcome. A passing update reports that outcome, the material wait and the next action rather than listing activity.

## Anti-patterns

- Reporting activity volume as progress.
- Mixing forecast with fact.
- Reproducing the full work log.
- Adding unsupported traffic-light labels.

## Stop

Stop with a concise draft containing evidence, current state and next action.
