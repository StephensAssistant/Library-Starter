# Create a Skill

GitHub-only format: create the canonical item in this repository on `staging`, using this folder's current `README.md`, `_TEMPLATE.md` and schema where applicable; do not substitute ChatGPT Library, Google Drive or another external document.
1. Search existing Skills and Playbooks. Create only for a distinct reusable technique, not a one-off procedure.
2. Copy `_TEMPLATE.md`. Fill its input/outcome, routing, decision/recovery, benchmark and source/verification fields. Apply Skills/README.md's explicit capability contract; no unresolved required value may become an implicit default or a guessed PASS. Keep the required sections concise and proportionate to the owned technique. Define unambiguous scope, applicable inputs/outputs, prerequisites, method, limits, failure/decision conditions and observable verification proportionately to the technique. For a Playbook support gap, search/reuse first; amend the same owner or create only a distinct missing capability, test the gap and affected caller, and obtain required independent review before workflow approval. Follow Workflows/README.md for supporting coverage evidence.
3. Reserve `SKILL` through the serialized ID workflow. Use `current` or `superseded` only. Add evidenced reciprocal links. Add the intent-routing contract and benchmark case before candidate validation.
4. Save the authorised canonical source and mandatory companions to `staging` through the mechanical source-save transaction, preserve concurrent work and verify exact saved content. Source-save authority does not authorise PLAY-0059, PLAY-0056, candidate validation, Actions or merge; use those workflows only under their applicable scheduled or explicit one-off authority.

Before source save, assess the result against Skills/README.md's AI authoring guidance. Keep domain-specific instructions, local failure lessons and observable output checks; do not add generic sections merely to fill a pattern. Preserve the baseline and use SKILL-0194 for material behaviour changes. Keep unexecuted cases and unavailable platform evidence explicit. Follow the target host's current format only if packaging is separately authorised; a governed record is not an installed runtime skill.

Stop after creation and source readback; distinguish saved source from accepted candidate or merged delivery.
