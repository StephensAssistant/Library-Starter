# Milestone Acceptance Evidence

Determine whether a milestone outcome is evidenced against its acceptance condition.

## When to use

Use when deciding whether a milestone has been achieved, remains incomplete or is only temporarily bridged.

## Method

1. State the milestone acceptance condition.
2. Identify direct proof such as validated data, working output, source availability, deployment state or an authorised UAT decision.
3. Count outcomes, not activity volume; scripts, queries and meetings matter only when they advance the acceptance condition.
4. Distinguish temporary technical parity from native completion.
5. Record achieved evidence, unmet acceptance conditions and the current milestone state.
6. Hand off status writing, forecasting and waiting-versus-blocked classification to their action-specific Skills.

## Benchmark case

A migrated report matches current values but still depends on a legacy bridge. A passing application records parity evidence while refusing to call native migration complete.

## Anti-patterns

- Fabricating percent complete.
- Treating row count or tasks touched as outcome progress.
- Calling a bridge a completed migration.
- Claiming completion without acceptance evidence.

## Stop

Stop with an evidenced achieved or not-achieved milestone verdict and the precise missing proof.
