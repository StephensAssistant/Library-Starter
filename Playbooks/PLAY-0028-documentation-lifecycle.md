# Documentation Lifecycle — Creation, Update, Retirement

## Trigger

A document/Artifact/Knowledge/Decision needs creation, update or supersession.

## Method

Find the canonical home; preserve the existing ID. Write only needed content in the appropriate native/Markdown format. Add factual source/parent/successor links and verify content and reciprocal relationships. An authorised Library create/update saves the source to `staging` only; it does not invoke PLAY-0056. PLAY-0056 runs only under AGENTS.md's enabled approved schedule naming both PLAY-0059 and PLAY-0056, or an explicit current-conversation named single-use one-off exception; a save or stage request is neither. Required acceptance and candidate validation remain separate from this source write.

## Stop

One verified canonical source draft staged within authority, with required acceptance/candidate validation explicitly complete or pending; staging alone is not accepted filing. Preserve history/Reference snapshots; no Drive/PATCH promotion, duplicate document or automatic new Decision for an unresolved question.

AGENTS.md owns shared authority, evidence reuse and task boundaries.

## Addy Osmani reference-method extension — 2026-11-01

When a decision rationale belongs in the documentation already in scope, follow the existing location, format, identifier and numbering convention. Capture the context and constraints, selected decision, alternatives considered and consequences, including material trade-offs and uncertainty. Do not create a separate Decision merely because this structure is useful.

When an accepted decision changes, preserve the earlier rationale as history and identify what supersedes it in the authorised canonical record. Do not silently rewrite the historical choice as though the new decision had always applied. Check that prose edits retain names, quantities, conditions and qualifiers supported by the source evidence. This technique adds no document-creation, relationship-update, staging, acceptance or promotion authority.
